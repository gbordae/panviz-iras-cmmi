> Modalidad: autoguiada o en reunión de equipo.

---

## Puntos clave

1. El oráculo se define **antes** de codificar, no después.
2. Cada entregable pasa por `plantilla_revision.md` antes de avanzar de etapa.
3. No conformidades → `plantilla_no_conformidad.md` → cierre documentado.
4. Los commits siguen el patrón `tipo: descripcion`; las etiquetas marcan baselines.
5. La reducción de carga documental es intencional: Markdown + Git reemplaza herramientas pesadas.
